# Chips Poker: описание, план и возможные доработки

Документ собран по содержимому репозитория (код, конфигурация, документация) и прогону
серверных тестов. Дополняет [README.md](../README.md), [ARCHITECTURE.md](ARCHITECTURE.md) и [API.md](API.md).

## 1. Описание проекта

**Chips Poker** — социальная платформа No-Limit Texas Hold'em в реальном времени.
Игровая валюта — виртуальные фишки без денежной ценности: нет оплаты, покупок,
вывода и передачи фишек. Каждый новый аккаунт получает стартовый бонус 10 000 фишек.

Ключевые свойства:

- **Авторитетный сервер.** Клиент отправляет только намерения (`call`, `raise to 400`).
  Стеки, банки и выплаты считает сервер; браузер баланс не присылает.
- **Игровой движок в памяти.** Столы живут в `TableManager` / `TableRuntime`, а в
  PostgreSQL пишутся только кошелёк, журнал фишек, история раздач и статистика.
- **Лиги.** Доступ к столам открывается по суммарному выигрышу (`User.totalWon`),
  а не по текущему балансу. Четыре лиги: Новичок, Любитель, Профи, Хайроллер.
- **Экономика.** Append-only журнал `ChipTransaction`; бесплатное пополнение до
  минимального buy-in и ребай при нуле.

### Состав репозитория

| Часть | Технологии | Назначение |
| --- | --- | --- |
| `apps/server` | Node 20.11+/22, TypeScript, Express, Socket.IO, Prisma, Zod, Pino, Vitest | REST API, WebSocket-шлюз, движок Hold'em, работа с БД |
| `apps/web` | React 18, Vite, React Router 7, socket.io-client | SPA: вход, лобби, стол, профиль, лидерборд |
| Инфраструктура | PostgreSQL 16, Redis 7, nginx, Docker Compose | Хранение, кэш/адаптер Socket.IO, раздача SPA и прокси |
| Запуск | `start.ps1`, `docker-compose.yml` | Локальный запуск на Windows и полный стек в Docker |

### Размер и структура кода

- Серверный TypeScript: около 4 100 строк, крупнейшие файлы — `engine.ts` (901),
  `table-runtime.ts` (556), `table-manager.ts` (448).
- Веб-приложение: около 1 900 строк только в `pages/`, плюс компоненты и контексты.
- Тесты: 2 файла, 17 тестов (оценка руки, движок), **все проходят**
  (`npm test`, прогон 746 мс).
- Миграций БД одна: `20260101000000_init`.

### Основные модули сервера

| Модуль | Роль |
| --- | --- |
| `auth/` | Регистрация, вход, bcrypt, JWT с `tokenVersion`, сброс пароля, отпечаток устройства |
| `profile/` | Статистика, история раздач, смена ника и аватара |
| `lobby/` | Список столов, блокировки лиг, счётчики игроков |
| `leaderboard/` | Топ-100 за всё время / неделю / сегодня с кэшем 45 с |
| `game/engine.ts` | Состояние раздачи: улицы, ставки, side pots, выплаты |
| `game/evaluator.ts`, `cards.ts` | Оценка 7-карточной руки, колода на `crypto.randomInt` |
| `game/table-runtime.ts` | Один стол: рассадка, таймеры, чат, ревизии состояния |
| `game/table-manager.ts` | Реестр столов, кошелёк, сохранение раздач, восстановление после рестарта |
| `realtime/gateway.ts` | Socket.IO: JWT в handshake, комнаты, валидация событий |

Столы: 9 штук. Новичок — 2×6-max и 1×9-max, остальные лиги — по 6-max и 9-max.

### Интерфейс и API

- REST: `/api/auth/*`, `/api/profile/*`, `/api/lobby/*`, `/api/leaderboard`, `/api/health`.
- Socket.IO: `table:join`, `table:leave`, `table:action`, `table:chat`, `table:rebuy`,
  `table:sitout`; сервер шлёт персонализированный снимок стола (карты видит только владелец).
- Тема оформления — тёмная «казино» (изумрудный и золотой), адаптив под телефон.

## 2. Текущее состояние

**Сделано:**

- Полный игровой цикл: блайнды, ротация баттона, легальные действия, минимальный рейз,
  all-in, side pots, split pot, автомакинг проигравших рук, тайм-банк.
- Серверная валидация всех REST-тел и Socket-событий через Zod, Helmet, CORS allow-list,
  rate-limit, проверка картинок по magic bytes, ограничение размера payload.
- Транзакции кошелька в `Serializable`, журнал фишек, восстановление «зависших» ставок
  после падения процесса (`RECOVER_TABLE_STAKES`).
- Docker Compose и локальный Windows-лаунчер с изолированным кластером PostgreSQL на порту 55432.
- Документация: архитектура, модель данных, REST и Socket.IO API.

**Проверено при подготовке этого документа:**

- `npm test` — 17/17 тестов зелёные (оценка рук и движок).
- Не проверялись: `npm run typecheck`, `npm run build`, работа в браузере, Docker-сборка,
  нагрузочные тесты.

## 3. План развития

### Этап 1. Надёжность и безопасность (приоритет высокий)

1. **Убрать небезопасные значения по умолчанию.**
   - В `config.ts` `DEVICE_COOKIE_SECRET` по умолчанию равен `dev-device-cookie-secret-change-me`.
   - В `docker-compose.yml` `JWT_SECRET` имеет fallback `change-me-in-production-change-me-please`.
   - Пароль БД `poker/poker` прописан в compose.
   - Нужно: в production падать при старте, если секреты не заданы или равны дефолтам.
2. **Не хранить личный домен в репозитории.** В `start.ps1` (строка 140) прописан
   `dimitrius.cloudpub.ru`. Вынести в переменную окружения или локальный конфиг.
3. **Почистить устаревшие пути.** `xd.txt` указывает на `F:\opencode\poker`, а проект лежит
   в `F:\claudecode\poker`.
4. **Выровнять документацию с кодом.** `ARCHITECTURE.md` ссылается на `game/deck.ts`, а в коде
   файл называется `game/cards.ts`. Проверить остальные ссылки в README и ARCHITECTURE.
5. **Добавить систему контроля версий.** Сейчас каталог не является git-репозиторием. Без
   истории нельзя безопасно откатывать изменения движка.

### Этап 2. Тестирование

6. **Покрыть не тестами:** `TableManager` (кошелёк, top-up, cash-out, recovery), `gateway`
   (JWT handshake, отказ при смене `tokenVersion`, валидация событий), `auth` (регистрация,
   сброс пароля, multi-account), `leaderboard`.
7. **Интеграционные тесты** REST с supertest (уже есть в devDependencies) против тестовой БД.
8. **Тесты на инварианты движка:** сохранение суммы банка (zero-sum), отсутствие утечки
   чужих карт в снимках, таймауты.
9. **Включить typecheck и build в CI** (GitHub Actions или аналог): `npm run typecheck`,
   `npm test`, `npm run build`, сборка Docker-образов.
10. **Нагрузочное тестирование** Socket.IO (например, k6 или artillery): цель — 500 одновременных
    игроков, которую сейчас заявляет документация, но не проверяли.

### Этап 3. Продуктовые функции

11. **Восстановление стола после рестарта.** Сейчас раздача прерывается, фишки возвращаются, чат
    теряется. Можно сохранять снимок стола в Redis или БД.
12. **Чат:** история сейчас в памяти (`CHAT_HISTORY_LIMIT`). Добавить модерацию: скрытие,
    жалобы, бан.
13. **Друзья и приватные столы.** Пригласительные ссылки, приватные комнаты с паролем.
14. **Турниры и сит-н-гоу.** Новый тип стола с блайнд-уровнями и выбыванием. Отдельный движок
    расписания.
15. **Достижения и сезоны.** Сейчас только лидерборды по периодам; сезонный сброс и награды

16. **Подтверждение email.** Сейчас при отсутствии SMTP ссылки сброса пишутся в лог.
    Для публичного запуска нужна верификация адреса.
17. **Локализация.** Интерфейс и названия лиг на русском; добавить английский через i18n.
18. **Push-уведомления** о ходе «твоя очередь» (после выхода PWA, см. раздел «Мобильная версия»).

### Этап 3б. Мобильная версия (игра с телефонов)

Сайт уже частично адаптивен: в `apps/web/index.html` есть `viewport` с `viewport-fit=cover`,
а в `apps/web/src/styles.css` есть медиазапросы на 1180, 980, 760 и 480 px. Полноценная
проверка на телефонах и игровой интерфейс для тачскрина ещё не сделаны.

М1. **Аудит на реальных устройствах.** Проверить iPhone (Safari) и Android (Chrome) в
    портрете и ландшафте: лобби, стол, профиль, лидерборд, вход. Фиксировать обрезку
    элементов, горизонтальный скролл и переполнение экрана.
М2. **Игровой стол для узкого экрана.** Стол 6-max и 9-max на телефоне: места игроков,
    карты, банк, панель действий (fold, check/call, bet/raise, all-in) должны помещаться
    без прокрутки. Для ландшафта — отдельная компоновка.
М3. **Тач-управление.** Крупные зоны нажатия (не менее 44×44 px), слайдер или поле ставки
    с кнопками ±, защита от случайных нажатий «все-ин» и «фолд», отключение зума по
    двойному тапу там, где он мешает.
М4. **Безопасные зоны и клавиатура.** Учесть `env(safe-area-inset-*)` (вырезы, нижняя
    панель iOS), высоту экрана через `dvh` вместо `100vh` (адресная строка браузера),
    поведение полей ввода при появлении экранной клавиатуры в чате и на формах входа.
М5. **Производительность на слабых устройствах.** Проверить плавность анимаций карт и
    фишек, отключать тяжёлые эффекты при `prefers-reduced-motion` и на слабом железе;
    замерить размер JS-бандла (сейчас один чанк `index-*.js`) и при необходимости разбить
    по маршрутам через `React.lazy`.
М6. **Установка как приложение (PWA).** Manifest, иконки, service worker для кэша статики,
    запуск без адресной строки. Важно: игровой сокет не кэшировать, офлайн-режим не нужен.
М7. **Автотесты интерфейса.** Playwright-сценарии с эмуляцией телефонов (viewport 375×667,
    390×844 и планшет) для входа, посадки за стол и хода в раздаче. Добавить в CI.

Критерий готовности: все основные сценарии (регистрация, посадка, полная раздача,
выход из стола) проходят на iPhone SE, среднем Android и планшете без горизонтальной
прокрутки и без скрытых кнопок действий.

## 5. Что уже работает и что важно не сломать

- Инвариант «сумма выплат равна сумме вложений» в каждой раздаче.
- Сервер не доверяет клиенту ни стекам, ни суммам.
- Buy-in и выход со стола проходят через `Serializable`-транзакции с записью в журнал.
- Карты соперников никогда не уходят в общий broadcast; снимки персонализируются по сокету.

Любое изменение в `engine.ts`, `table-manager.ts` или `auth/` должно сопровождаться тестом
из раздела 3, этап 2.
